# B3.6 Observability Foundation - Implementation Plan

## 1. Goal
Implement a minimal, framework-independent Observability Foundation package. This establishes the boundary for operational logging, metrics, and tracing, strictly decoupled from Laravel and Monolog.

## 2. Abstractions
- **Logging**: A generic `Logger` interface for operational logs (`info`, `error`, `warning`, `debug`, `critical`).
- **Metrics**: A `Metrics` interface for telemetry (`increment`, `gauge`, `timing`).
- **Tracing**: A `Tracer` interface that can start `Span` instances to measure operation boundaries.
- **Correlation**: A `CorrelationId` value object to tie logs, spans, and metrics together across boundaries.

## 3. Context Safety
To prevent accidental model serialization and domain leakage, a `LogContext` value object will be used for all log metadata. Similar to Audit's `Metadata`, it recursively rejects objects, resources, and closures, allowing only scalars and nulls. Documented explicitly: scalar secrets (passwords, tokens) are the caller's responsibility to omit.

## 4. Failure Behavior
Unlike Audit (which fails-closed), Observability strictly **fails-open (best-effort)**.
Operational telemetry failures must never alter or halt business logic. Implementations of the `Logger`, `Metrics`, and `Tracer` contracts must swallow underlying adapter exceptions (or write to a bare PHP `error_log` fallback) rather than bubbling them up to the application.

## 5. Laravel Adapter Boundaries
B3.6 will provide `InMemory` Application-layer implementations for testing. Future phases will introduce a `LaravelLogAdapter` or `OpenTelemetryAdapter` within the Infrastructure layer. The Public API will contain no PSR-3, Monolog, or Laravel references.

## 6. Audit & Dependency Separation
- Observability does not depend on Audit.
- Audit does not depend on Observability.
- No `SharedKernel` Clock is introduced, as timestamps are adapter/runtime concerns for logs/metrics.
- The module has 0 internal Foundation dependencies.

## 7. Extension Model
Any business module can resolve `Logger`, `Metrics`, or `Tracer` and emit events using their own nomenclature. The Foundation does not own or restrict product-specific names, providing only the generic emission mechanism.

## 8. Rollback Considerations
Rollback entails removing the `Base\Foundation\Observability` directory and reverting the `deptrac.php` additions. No database schemas are involved.
