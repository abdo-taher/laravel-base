# B3.2 Configuration Foundation — Implementation Plan

## Status

IMPLEMENTED — VALIDATION PASSED

## 1. Configuration Ownership

Configuration Foundation owns:

- the retrieval contract (`ConfigurationRepository`)
- the source/provider contract (`ConfigurationSource`)
- the composition and precedence engine (`LayeredConfigurationRepository`)
- the definition/declaration model (`ConfigurationKey`, `ConfigurationDefinition`)
- validation infrastructure (required vs optional, type assertion)
- the extension contract (`ConfigurationSourceContributor`)

Configuration Foundation does **not** own:

- the *meaning* of any configuration key
- wallet.*, identity.*, notifications.*, or any other package-specific vocabulary
- database-backed settings (Platform Settings — deferred)
- feature flags (deferred)
- tenant configuration (deferred)
- remote/dynamic configuration (deferred)
- secret storage or retrieval

Each consuming package declares its own typed keys as value objects in
its own namespace and registers a source with its defaults.

---

## 2. Configuration Model

### 2.1 Typed Key

A `ConfigurationKey<T>` value object captures:

- the key path string (e.g., `"manifest.max_file_size_bytes"`)
- the expected PHP type tag (string, int, bool, float, array)
- whether the key is required or has a default

Because PHP generics do not exist at runtime, the type is expressed as
a string type tag and enforced at retrieval time via explicit assertion.
Keys are value objects: readonly, no framework coupling.

### 2.2 ConfigurationDefinition

A `ConfigurationDefinition` value object captures a key together with
its default value (or marks it as required with no default). Used by
sources to declare what they provide.

### 2.3 ConfigurationSource

An interface that returns `array<string, mixed>` for its owned keys.
Sources are registered with an explicit integer priority. Higher
priority overrides lower.

### 2.4 ConfigurationRepository

The primary Public contract. Given a `ConfigurationKey`, returns a
typed value or throws `ConfigurationKeyMissing` / `ConfigurationTypeMismatch`.

Provides:
- `get(ConfigurationKey $key): mixed` — typed retrieval, throws on missing required
- `has(ConfigurationKey $key): bool` — presence check
- `getOrDefault(ConfigurationKey $key, mixed $default): mixed` — safe retrieval
  with caller-supplied fallback (does not require a definition default)

### 2.5 ConfigurationSourceContributor

The extension contract. An external contributor (e.g., a project
extension) implements this to supply additional sources. Compatible
with the ExtensionRegistry contributor model but does not depend on
ExtensionRegistry at this stage.

## 3. Precedence Model

Accepted precedence (lowest to highest priority integer):

```
1  — Package defaults        (registered by each package's service provider)
10 — Project configuration   (registered by the host application)
50 — Extension override      (registered by project extensions via
                              ConfigurationSourceContributor)
100— Environment/runtime     (registered explicitly when allowed; never
                              implicit env() calls in contracts)
```

Rules:

- Priority integers are explicit. No magic ordering by registration order.
- When two sources share the same priority, the last one registered wins
  for that key. This is deterministic within a single registration pass
  because service providers register in a defined order.
- Priority values are open (callers may use any integer). The above
  values are conventions, not hardcoded constants in the package.
- The precedence model is tested explicitly: a higher-priority source
  must override a lower-priority one for the same key.

This precedence is recorded here and in the README. It does not change
silently.

---

## 4. Validation Behaviour

- A `ConfigurationKey` declared as required (`isRequired: true`, no
  default) throws `ConfigurationKeyMissing` when no source provides it.
- A value present but of the wrong PHP type throws
  `ConfigurationTypeMismatch`.
- Optional keys with a definition default return the default silently.
- `has()` never throws — it returns false for absent keys.
- `getOrDefault()` never throws — caller-supplied default is used when
  absent.
- Validation is fail-closed: no silent coercion or type juggling.

---

## 5. Secret Safety

- `ConfigurationKey` has no special "secret" flag in B3.2 (deferred).
- The package does not encourage storing secrets in source arrays: the
  README explicitly states that secrets must not be placed in
  `ConfigurationSource` implementations.
- No `.env` reading, no `env()` calls, no secret manager.
- Future: a `SecretReference` value object may be introduced as an
  opaque placeholder; secret resolution is a separate capability.

---

## 6. Laravel Boundary

- All Public contracts are Laravel-free.
- A `LaravelConfigurationSource` adapter lives under `Infrastructure/`
  only. It reads from Laravel's `Config` repository and implements
  `ConfigurationSource`. It is used by the `ConfigurationServiceProvider`
  to register the project configuration source at priority 10.
- The `ConfigurationServiceProvider` binds `ConfigurationRepository` to
  `LayeredConfigurationRepository` in the Laravel container.
- No `config()`, `Config::`, `Facades`, or `env()` calls appear in
  `Public/` or `Application/`.

---

## 7. Extension / Customisation Model

`ConfigurationSourceContributor` is a Public contract (interface).
A project extension implements it and returns one or more
`ConfigurationSource` instances with their priority.

At B3.2 the service provider calls `ConfigurationSourceContributor`
instances passed directly via constructor injection (or registered
through the Laravel container as tagged services). This keeps the
design decoupled from ExtensionRegistry internals — when the full
runtime extension discovery is wired up (post-B3), contributors will be
discovered automatically.

No modification to ExtensionRegistry is required.

## 9. Public Contracts Introduced

| Contract | Kind | Purpose |
|---|---|---|
| `ConfigurationRepository` | interface | Primary read contract — get, has, getOrDefault |
| `ConfigurationSource` | interface | Key-value provider with priority |
| `ConfigurationSourceContributor` | interface | Extension hook — supplies additional sources |
| `ConfigurationKey` | readonly value object | Typed key: path, type tag, required flag, optional default |
| `ConfigurationDefinition` | readonly value object | Pairs a key with its declared default for source registration |
| `ConfigurationKeyMissing` | exception | Required key absent from all sources |
| `ConfigurationTypeMismatch` | exception | Value present but wrong PHP type |

## 10. Dependencies

Configuration Foundation has **no dependencies on other Foundation
packages** (no SharedKernel, no Manifest, no CapabilityRegistry, etc.).

`ConfigurationKey` type tags are plain PHP strings — no SharedKernel
type system is needed.

The Laravel `Infrastructure` adapter depends on `Illuminate\Contracts\Config\Repository`
(the contracts package, not the full framework) but this is
Infrastructure-only and does not cross into Public.

### Deptrac updates required

- Add `Base.Foundation.Configuration` layer.
- Permit `Tests` to access it.
- No other Foundation layer rules change — Configuration has no
  cross-package Foundation dependencies.

## 11. Tests

### Positive

- `LayeredConfigurationRepository` returns a typed string value from a
  registered source.
- A higher-priority source overrides a lower-priority source for the
  same key.
- Multiple sources at different priorities compose deterministically.
- `has()` returns true when a key is present.
- `getOrDefault()` returns the default when key is absent (no throw).
- Optional `ConfigurationKey` with a definition default returns the
  default when no source provides a value.
- `ConfigurationDefinition` exposes key and default correctly.
- `ConfigurationKey` value object is readonly (immutable).
- `ConfigurationDefinition` value object is readonly (immutable).

### Negative

- `get()` throws `ConfigurationKeyMissing` for a required key with no
  source providing it.
- `get()` throws `ConfigurationTypeMismatch` when value exists but is
  the wrong type.
- Two sources at the same priority: last registered wins (deterministic).
- Registering a source with a duplicate priority behaves predictably
  (documented and tested).

### Architecture tests

- No Public contract file imports `Illuminate\*`.
- No Public contract file imports any other Foundation package.
- `ConfigurationKey` is a readonly class.
