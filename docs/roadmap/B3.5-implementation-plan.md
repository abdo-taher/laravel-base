# B3.5 Audit Foundation - Implementation Plan

## 1. Goal
Implement a minimal, framework-independent Audit Foundation package that provides the core abstractions for recording immutable audit events.

## 2. Audit Event Model
The central model is the `AuditEvent` readonly class. It captures:
- `eventId`: A unique identifier (string/UUID) to ensure idempotency and traceability.
- `action`: An `Action` value object representing what happened.
- `principal`: A `Principal` value object (from Identity). Optional, to support system-generated events.
- `subject`: A `SubjectRef` value object identifying the entity modified (optional).
- `timestamp`: A `DateTimeImmutable` representing when the event occurred in UTC.
- `metadata`: A `Metadata` value object containing additional context.

## 3. Actor Representation
We consume `Base\Foundation\Identity\Public\ValueObjects\Principal`. 
If a human or system actor triggered the event, this field is populated. If it's a purely background system event with no distinct actor, this field can be `null`.

## 4. Action Representation
An `Action` readonly value object wrapping a non-empty string. 
Foundation will **not** define business actions (like `order.approve`). Modules define and emit their own action names.

## 5. Subject/Resource Representation
A `SubjectRef` readonly value object containing:
- `type`: non-empty string (e.g., `'order'`)
- `id`: non-empty string (e.g., `'ORD-123'`)
This avoids capturing arbitrary domain models directly.

## 6. Metadata Model
A `Metadata` readonly value object wrapping an `array<string, mixed>`.
To ensure immutability and security:
- The constructor will deeply traverse the array.
- It will reject any PHP objects (to prevent accidental capture of Eloquent models, services, or secrets attached to objects).
- Only scalars, arrays, and nulls are permitted.

## 7. Timestamp Strategy
Since there is no `Clock` in `SharedKernel`, we will introduce an Audit-local `Clock` interface in `Base\Foundation\Audit\Public\Contracts\Clock` returning `DateTimeImmutable`. 
An Application-layer `SystemClock` will implement this.

## 8. Write Contract & Storage Boundary
The primary Public API is:
```php
interface AuditRecorder {
    public function record(AuditEvent $event): void;
}
```
For B3.5, we will provide an `InMemoryAuditRecorder` in the Application layer. No database tables or Laravel infrastructure will be introduced. 

## 9. Failure Policy
If an audit recording fails (e.g., storage unreachable), it must fail-closed to prevent silent loss of audit trails. 
The `AuditRecorder::record()` method will throw an `AuditRecordingFailed` exception if the underlying sink fails. Business workflows will fail if their audit emission fails, ensuring strict compliance.

## 10. Identity Relationship
Audit imports `Base\Foundation\Identity\Public\ValueObjects\Principal`. It does not depend on AccessControl. This maintains a clean dependency graph.

## 11. Extension Model
There is no central event registry required. Business modules extend the audit log simply by constructing an `AuditEvent` with their own `Action` string and passing it to the `AuditRecorder`.

## 12. Security
- Object rejection in `Metadata` prevents leaky domain models.
- The `AuditRecordingFailed` exception will not expose internal database/storage errors to the user, only the failure of recording.

## 13. Tests
- **Positive**: Event construction, metadata validation (scalars/arrays), in-memory recorder, timestamp generation.
- **Negative**: Missing/empty strings, objects in metadata, architecture tests ensuring no product vocabulary (`order.*`) and no Laravel dependencies.

## 14. Rollback Considerations
Rollback involves removing the `Base\Foundation\Audit` namespace, the directory, and reverting `deptrac.php` additions.
