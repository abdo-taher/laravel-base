# B6.2.2 Media HTTP Upload Plan

## 1. Implementation Decision
We will implement a standard upload-first HTTP integration within `Platform.Media`. The HTTP layer will reside in a new `Presentation/Http` namespace, keeping the domain/application contracts (`MediaUploader`) framework-free.

## 2. HTTP Adapter Ownership/Location
- **Controller**: `packages/base/Platform/Media/Presentation/Http/Controllers/MediaUploadController.php`
- **Resolver Contract**: `packages/base/Platform/Media/Presentation/Contracts/MediaAccessScopeResolver.php`
- **Resolver Implementation**: `packages/base/Platform/Media/Presentation/Http/Resolvers/RequestMediaAccessScopeResolver.php`
- **Routes**: `packages/base/Platform/Media/Presentation/Routes/api.php`

## 3. Exact Route
`POST /api/media`

We will wrap the route in `api` middleware and `/api` prefix inside `MediaServiceProvider::boot()`, ensuring it matches typical Laravel API conventions while keeping the logical route reusable.

## 4. Exact Request Format
```http
POST /api/media
Content-Type: multipart/form-data

file=<binary>
```
Only one file per request. No chunking or multiple files.

## 5. Exact Success Response/Status
HTTP `201 Created`
```json
{
    "reference": "med_xxxxxxxxx"
}
```

## 6. MediaAccessScope Resolution Model
A host-facing contract `MediaAccessScopeResolver` will be responsible for translating the current Laravel Request into a stable `MediaAccessScope`. The default implementation will be bound in `MediaServiceProvider`.

## 7. Authenticated Behavior
For authenticated users, the resolver will return a stable scope based on the user ID, e.g., `principal:<id>`. The HTTP code will not hardcode a Product-specific User model, relying only on Laravel's Auth abstractions.

## 8. Guest Behavior
Guest uploads will be explicitly rejected (HTTP 401) for MVP safety. The implementation will not support guest uploads right now, as ensuring stable scope for later attachment requires reliable session management which is out of scope for this phase.

## 9. Scope Stability Proof
Tests will verify that multiple uploads by the same user produce the same scope, and that a `MediaSynchronizer` call with a different user's scope rejects the `TEMPORARY` media.

## 10. UploadedFile -> MediaUploader Adaptation
The Controller will:
1. Open a readable stream using `$request->file('file')->getRealPath()`.
2. Extract the original filename via `$request->file('file')->getClientOriginalName()`.
3. Pass the stream, filename, and resolved scope to `MediaUploader::upload()`.
4. Ensure the stream is closed safely in a `finally` block if not already closed.

## 11. File/MIME/Size Validation Ownership
Framework-level request validation will strictly verify:
- `file` is present.
- `file` is an uploaded file.
- `file` does not exceed a global max transport size (e.g., 20MB).
No MIME validation will occur here; `MediaUploader` retains authoritative MIME checking.

## 12. Rate Limiting Decision
We will apply Laravel's native `throttle:api` middleware to the route. By default, this provides standard API rate limiting. We avoid creating a custom RateLimiter abstraction.

## 13. Error Mapping
- **Validation Failure**: HTTP 422 (native).
- **Unauthenticated**: HTTP 401.
- **MediaUploadFailed**: HTTP 422 (with generic "Upload failed" message).
- **Unexpected Error**: HTTP 500 (native, secrets not exposed).
Raw exception messages, paths, and internal keys will never be exposed.

## 14. Security / Leak Prevention
The HTTP response strictly returns only the `reference`. `MediaAccessScope`, `storage_key`, and database IDs are fully abstracted away. File original name is passed only as untrusted metadata to the Uploader.

## 15. Route Registration/Removability
Routes are loaded via `$this->loadRoutesFrom()` inside `MediaServiceProvider`. Removing the package or its provider will cleanly remove the route. No uploads can occur during application boot.

## 16. End-to-End Upload/Reference/Sync Proof
A feature test will execute:
1. `POST /api/media` -> 201 Created.
2. Resolve the same scope via a test user.
3. Call `MediaSynchronizer::sync` with `MediaSlotChanges::fromArray(['gallery' => [$ref]])`.
4. Assert successful state transition from `TEMPORARY` to `ATTACHED`.

## 17. Named Business-Key Proof
The same end-to-end test will demonstrate using domain-specific slot names (e.g., `main_image`, `gallery`) directly with `MediaReference` string values, proving the model.

## 18. Product JSON-only Integration Guidance
Product module create/update endpoints should accept standard JSON payloads (e.g., `{"main_image": "med_abc"}`) rather than dealing with multipart form data. This simplifies Product controllers and delegates file handling to Media.

## 19. Presigned Evolution Compatibility
The `POST /api/media` payload could eventually evolve into a two-step process (request intent -> upload to S3 -> confirm) while leaving Product module business JSON payloads untouched.

## 20. Quality Gates
Run `composer test`, `composer analyse`, `composer architecture` and ensure Deptrac boundaries are respected.
