# B6.4 Minimal Product Reference Module & Execution Plan

## Mission
Prove the complete Product layer architecture, dependency resolution, Media attachment flow, and module boundaries through a minimal, disposable reference implementation (`Modules\ReferenceCatalog`).

## Constraints
- Do NOT build a full production domain (no pricing, inventory, complex rules).
- Do NOT commit, tag, or push.
- Maintain strictly internal persistence ownership (Product Eloquent model must NOT leak to Public).
- Exclusively interact with `Platform.Media` through Public contracts (no Eloquent morph relations in Product space).

## Expected Capabilities
- Requires: `media.attachments`
- Resolves: `Platform.Media` -> `Platform.Files` (transitive via capability dependency).

## Milestones

+ [x] **P1 - Module Bootstrap**
  - Create `modules/ReferenceCatalog/` and required subdirectories.
  - Implement B6.1 contract-compliant `module.json` and `ReferenceCatalogServiceProvider`.

+ [x] **P2 - Domain & Persistence**
  - Create migration for `reference_items` table (id, name, timestamps - NO media FKs).
  - Create internal `ReferenceItem` Eloquent model.

+ [x] **P3 - Public API & Media Boundaries**
  - Define `ReferenceItemView` DTO.
  - Define `ReferenceCatalogCreator` (if applicable) or command objects.
  - Define Media Slot configurations (cover SINGLE, gallery MULTIPLE) locally.
  - Define `MediaOwnerReference` logic internally.

+ [x] **P4 - Application Logic & Transactions**
  - Implement creation use case wrapper.
  - Assert transaction wraps ReferenceItem insertion + `MediaSynchronizer::sync()`.
  - Ensure rollback on missing/invalid media exceptions.

+ [x] **P5 - HTTP Presentation**
  - Define `POST /api/reference-items` route loaded by module service provider.
  - Implement request validation and safe response mapping.

+ [x] **P6 - Tests & Proofs**
  - Architecture Proof: `ReferenceCatalog` depends purely on Public Base contracts.
  - Resolution Proof: `ModuleManager` discovers the module and resolves `media.attachments` + transitives.
  - E2E Proof: Upload media via Platform, then create Product attaching the temporary media successfully.
  - Security Proof: Wrong scope media upload rejects product creation.
