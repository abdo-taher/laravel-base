No persistent package or module fixture directories will be added. Scenario fixtures exist only below the operating system temporary directory for the duration of each test.

## Validation Scenarios

### Expected Failures

1. Foundation imports a Platform Public contract.
2. Platform imports a Product Public contract.
3. An extension imports a Base internal implementation.
4. A Product module imports another Product module's internal class.
5. Two components form a circular dependency.

Each negative fixture must produce a non-zero Deptrac result. The PHPUnit test passes only when the invalid dependency is rejected.

### Expected Passes

1. Platform imports a Foundation Public contract.
2. Product imports a Platform Public contract.
3. An extension implements a Base Public extension contract.

Each positive fixture must produce a zero Deptrac result with no architecture violation.

## Architecture Rules Being Tested

- Foundation cannot depend on Platform or higher layers.
- Platform cannot depend on Product.
- Base internals are private to their owning package.
- Product module internals are private to their owning module.
- Cross-boundary imports target Public contracts only.
- Dependency direction is Product/Extension toward Base, never the reverse.
- Circular dependencies are forbidden.
- Extensions may implement explicit Base Public extension contracts.

## Isolation and Cleanup

- Every scenario receives a unique directory created with `sys_get_temp_dir()` and cryptographically random suffix data.
- Fixture source and Deptrac configuration are generated inside that directory.
- No temporary fixture path is added to Composer autoloading or production architecture configuration.
- A `finally` block recursively removes each scenario directory whether the assertion passes or fails.
- No skip rules or baseline files are used.
