# B5.1 Outbound Webhooks Implementation Plan

## 1. Objective
Design the minimum generic `Base\Specialized\OutboundWebhooks` capability. Its strict responsibility is to synchronously deliver a generic HTTP webhook request to an explicit outbound endpoint. The package must remain business-neutral, zero Base dependencies, framework-independent at the Public boundary, persistence-free, queue-free, retry-free, and Product-independent.

## 2. Scope
- Synchronous webhook dispatch via explicit endpoints.
- JSON-only payload transmission.
- POST-only HTTP method enforcement.
- Custom caller-defined HTTP headers (strictly sanitized and rejecting transport overrides).
- Deterministic 2xx success policy.
- Secure exception boundaries preventing secret/PII leaks.

## 3. Non-goals
- Inbound webhooks.
- Persistent endpoints/delivery history.
- Retry engines or dead-letter queues.
- Webhook dashboards.
- General-purpose HTTP client capabilities (e.g. GET/PUT/multipart).
- Native payload signing frameworks.
- Distributed idempotency management.

## 4. Package Boundary
- **Specialized Layer**: Located at `packages/base/Specialized/OutboundWebhooks`.
- Completely decoupled from `Notifications`, `Settings`, `Files`, or `Identity`.
- Exclusively concerns transport intent and synchronous delivery attempt.

## 5. Endpoint Model
- `WebhookEndpoint` (Value Object).
- Enforces structurally valid URL format.
- Rejects URL fragments (`#`).
- **HTTP/HTTPS Decision**: HTTP and HTTPS are structurally allowed. HTTPS is the expected secure standard. HTTP is documented as insecure and intended only for local/dev scenarios where deployment policy permits it. The value object avoids performing environment detection.
- **Endpoint Credentials**: WebhookEndpoint strictly rejects URL user-info and embedded credentials.
  - REJECT: `https://user:password@example.com/hook`
  - REJECT: `https://token@example.com/hook`
  - Query parameters may technically be present in the URL, but the package **does not claim query-string secrets are safe**. Callers **SHOULD NOT** place API keys or tokens in query strings because URLs are frequently logged by HTTP infrastructure. The preferred authentication transport is validated request headers via `WebhookHeaders`.

## 6. SSRF Boundary
**Core DOES NOT guarantee SSRF prevention.**
B5.1 core guarantees ONLY structural URL validation:
- Syntactically valid URL.
- http/https schemes according to accepted policy.
- No user-info.
- No fragments.
The package MUST NOT claim that the core or the Laravel HTTP client automatically prevents localhost access, private RFC1918 ranges, link-local addresses, cloud metadata endpoints, DNS rebinding, or internal DNS names. Network-level SSRF protection strictly belongs to deployment / egress policy or a future explicitly designed transport policy. No IP-blocking heuristics will be implemented in `WebhookEndpoint`.

## 7. HTTP Method Decision
**POST only.**
Webhooks are historically state-mutating event pushes. Enforcing POST prevents this capability from accidentally mutating into a generic HTTP SDK abstraction.

## 8. Payload Model
- `WebhookPayload` (Value Object).
- Must accept only recursively JSON-compatible values: `null`, `bool`, `int`, `float`, `string`, and nested arrays. Both JSON lists and JSON objects (associative arrays) are allowed.
- Strictly rejects objects, resources, closures, `NAN`, `INF`, and `-INF`. 
- Encoding must not rely on silent `json_encode` coercion. Encoding failures must cross as package-owned validation/dispatch failures (`InvalidWebhookPayload`), not raw `JsonException`.

## 9. Content Type
**JSON only.**
The transport will exclusively send payloads as `application/json`. Multipart, form-encoded, and XML are unsupported. `Content-Type` is strictly transport-owned and cannot be overridden by callers.

## 10. Header Model
- `WebhookHeaders` (Value Object).
- **Names**: Must be non-empty, conform to valid HTTP token-style characters, and reject CR/LF and null/control characters.
- **Values**: Must be strings and reject CR, LF, null bytes, and unsafe control characters.
- **Forbidden Headers**: Callers are explicitly prohibited from controlling transport-sensitive headers: `Host`, `Content-Length`, `Transfer-Encoding`, `Connection`, `Content-Type`, and `Accept-Encoding`.
- **Duplicates**: Headers are case-insensitive. Duplicate header-name registration (e.g., passing both `Authorization` and `authorization`) is strictly rejected during composition.

## 11. Webhook Request Model
- `WebhookMessage` (Value Object).
- Composed of: `WebhookEndpoint`, `WebhookPayload`, and an optional `WebhookHeaders`.

## 12. Dispatcher Model
- `WebhookDispatcher` (Public Contract).
- `public function dispatch(WebhookMessage $message): void;`
- The primary Public capability is the dispatcher.

## 13. Transport Contract Location
- `WebhookTransport` (Application Contract).
- Provider-substitution machinery (the Transport interface) is kept internal to the `Application` layer. It is NOT part of the `Public` API unless consuming packages genuinely need to implement the transport directly. `WebhookDispatcher` remains the primary Public contract.

## 14. HTTP Success Semantics
**Freeze exactly:**
- `200 <= status <= 299` -> successful synchronous delivery attempt.
- all other statuses -> `WebhookDispatchFailed`.

Successful return does NOT mean the receiver processed business semantics, that permanent delivery was achieved, or that future retries will succeed. No response body enters the Public result because dispatch returns `void`.

## 15. Redirect Guarantee
**B5.1 follows ZERO redirects.**
3xx is NOT success. The Laravel HTTP adapter must explicitly configure redirect following OFF; it will not rely on library defaults. This is a deliberate transport behavior to reduce secondary SSRF vulnerabilities.

## 16. Timeout Ownership
**Infrastructure configuration.**
Connect and request timeouts are configured directly within the Infrastructure transport adapter's composition. The Public API does not dictate timeouts.

## 17. Retry Ownership
**Caller / Application Composition.**
The core dispatcher executes EXACTLY ONE delivery attempt. If it fails, it throws. Asynchronous execution, queue wrappers, and retry logic belong to Laravel Jobs wrapping the dispatcher, not the B5.1 core.

## 18. Signing Decision
**Deferred to Caller / Composition.**
No native HMAC signing engine will be built in the B5.1 core. Callers are responsible for computing signatures and providing them via `WebhookHeaders` prior to dispatch.

## 19. Secret/PII Failure Boundary
Exceptions must **NEVER** include:
- Payload body.
- Response body.
- `Authorization` header value.
- `Cookie` value (if Cookie is supported).
- API keys or complete sensitive custom headers.
- Endpoint user-info (already structurally prohibited).

The complete endpoint URL itself should avoid appearing in generic errors due to potential query-string secrets. When endpoint identification is necessary for an exception, use a generic message or a sanitized scheme/host representation only. HTTP status code may be exposed.

## 20. Failure Model
- `WebhookException` (Base RuntimeException).
- `InvalidWebhookEndpoint` (Validation error).
- `InvalidWebhookPayload` (Validation error).
- `WebhookDispatchFailed` (Transport or non-2xx failure). Exposes status code but completely hides response body and sensitive payload.

## 21. Idempotency Decision
**Deferred.** Callers may manually inject an `Idempotency-Key` header if they require it.

## 22. Event-name Decision
**Deferred.** The transport does not mandate an event name. This is a Product-level concern.

## 23. Persistence Decision
**No package-owned persistence.** No tables, models, or migrations exist in B5.1.

## 24. Async/Queue Decision
**No package-owned queueing.** No `ShouldQueue` or Job abstractions in the Public/Application core.

## 25. Security Model
- **SSRF**: Structural URL validation only. Real protection belongs to egress policies.
- **Redirects**: explicitly disabled.
- **HTTP vs HTTPS**: Both structurally allowed; HTTPS intended for production.
- **Exceptions**: Actively strip response bodies, request headers, and payloads to prevent log leakage.

## 26. Dependency Graph
- **Required**: Zero Base packages.
- **Optional Integrations**: None.

## 27. Proposed Public API
```php
namespace Base\Specialized\OutboundWebhooks\Public\ValueObjects;
final readonly class WebhookEndpoint { ... }
final readonly class WebhookPayload { ... }
final readonly class WebhookHeaders { ... }
final readonly class WebhookMessage { ... }

namespace Base\Specialized\OutboundWebhooks\Public\Contracts;
interface WebhookDispatcher { public function dispatch(WebhookMessage $message): void; }

namespace Base\Specialized\OutboundWebhooks\Public\Exceptions;
class WebhookException extends \RuntimeException {}
final class InvalidWebhookEndpoint extends WebhookException {}
final class InvalidWebhookPayload extends WebhookException {}
final class WebhookDispatchFailed extends WebhookException {}
```

## 28. Proposed Application Components
```php
namespace Base\Specialized\OutboundWebhooks\Application;
interface WebhookTransport { public function send(WebhookMessage $message): void; }
final class DefaultWebhookDispatcher implements WebhookDispatcher { ... }
```

## 29. Proposed Infrastructure Adapter
```php
namespace Base\Specialized\OutboundWebhooks\Infrastructure\Adapters;
final class LaravelHttpWebhookTransport implements WebhookTransport { ... }
```

## 30. Proposed Package Tree
```
packages/base/Specialized/OutboundWebhooks/
├── Application/
├── Infrastructure/
├── Public/
├── module.json
└── OutboundWebhooksServiceProvider.php
```

## 31. module.json Capability
- `category`: `Specialized`
- `capabilities`: `outbound-webhooks.dispatch`

## 32. Deptrac Implication
Zero Base access grants. No Product access grants. Fully isolated.

## 33. Testing Strategy
- **Value Objects**: Strict URL validation, JSON-primitive enforcement, restricted header keys.
- **Dispatch**: Mocks `WebhookTransport` to verify success/failure mappings.
- **Security**: Assert that `WebhookDispatchFailed` exception traces omit payload/response body and raw URL query strings. Assert redirects are disabled in the Laravel HTTP adapter via fake client tests.
- **Architecture**: Enforce zero Base dependencies and zero framework leaks in Public.

## 34. Removability
The package acts as an isolated leaf. Removing it will not break Foundation or Platform.

## 35. Acceptance Criteria
- `WebhookDispatcher` successfully issues POST JSON requests.
- Exceptions securely obfuscate response bodies, payload, and query parameters.
- Deptrac validates 0 dependencies.
- 100% PHPStan level 8 pass.

## 36. Deferred Concerns
- Delivery persistence / Retry logs.
- Inbound webhooks.
- Native payload signing integration.

# Required Review Questions

**1. POST only or multiple HTTP methods?**
POST only.

**2. JSON-only or arbitrary body?**
JSON-only.

**3. Are custom headers supported?**
Yes, but transport-control headers (`Host`, `Content-Length`, `Content-Type`, `Transfer-Encoding`, `Connection`, `Accept-Encoding`) are actively rejected.

**4. Who controls timeout?**
The Infrastructure adapter via configuration during container binding.

**5. Are redirects followed?**
No. Redirects are disabled to prevent SSRF bypasses.

**6. What HTTP statuses mean success?**
200 <= status <= 299.

**7. Does core retry?**
No. Exactly one attempt.

**8. Does core queue?**
No. Core is synchronous.

**9. Does core persist?**
No. Zero database tables.

**10. Does B5.1 include signing?**
No. Deferred to caller composition.

**11. Does B5.1 depend on Foundation.Security?**
No. 

**12. Does endpoint validation claim SSRF protection?**
No. Core guarantees URL structural validity only.

**13. Who owns SSRF policy?**
Infrastructure transport adapters or external network egress proxies/policies.

**14. Can raw response bodies enter exceptions?**
No. Stripped to prevent PII/secret leakage.

**15. Can raw payload enter exceptions?**
No. 

**16. Is idempotency included?**
No. Caller can inject an `Idempotency-Key` header manually.

**17. Is event name required?**
No. 

**18. Does core have zero Base dependencies?**
Yes.

**19. Can package be removed independently?**
Yes.

**20. Does any Product concept leak?**
No.
