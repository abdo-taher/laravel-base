# B4.2 Files Implementation Plan

## 1. Purpose
The `Base\Platform\Files` package provides a generic, framework-independent, domain-neutral file and object storage capability. It acts as the canonical boundary between the Base ecosystem and the underlying storage infrastructure (e.g., local disk, S3).

## 2. Non-Goals
- **No Product Vocabulary**: It knows nothing about `product_id`, `user_id`, images, avatars, or media collections.
- **No Persistence Schema**: It does NOT include database migrations. The storage backend is the source of truth.
- **No Authorization**: Storage visibility (public/private) is separate from AccessControl.
- **No MIME/Malware Validation**: Security/virus scanning and strict MIME validation are deferred to dedicated pipelines.

## 3. Core Public API
- **Value Objects**:
  - `StorageKey`: Represents the logical identity and path of a file. Strictly validates against path traversal (`../`), absolute paths, and null bytes.
  - `FileVisibility` (Enum): `PRIVATE`, `PUBLIC`.
- **Contracts**:
  - `FileReader`: `read`, `readStream`, `exists`.
  - `FileWriter`: `write` (accepts string or resource), `delete`.
  - `FileStorage`: Combines Reader and Writer.
- **Exceptions**:
  - `FileException` (base)
  - `InvalidStorageKey`
  - `FileNotFound`
  - `FileStorageFailed`

## 4. Write & Read Semantics
- **Write**: Accepts `string` or `resource` (stream) to safely handle large files without loading them fully into memory. Fails closed (throws `FileStorageFailed` instead of returning false).
- **Read**: Provides both string-based `read()` and stream-based `readStream()` methods. Throws `FileNotFound` if the key does not exist.
- **Delete**: Returns `void`. If the file doesn't exist, it can either silently succeed or throw; typically, idempotent deletion (silent success) is preferred for distributed storage, but throwing `FileNotFound` if explicitly requested to delete something that doesn't exist is also valid. We will use idempotent deletion (succeed if missing).

## 5. Security & Path Traversal
`StorageKey` performs strict input validation. It rejects:
- Empty strings.
- Strings containing `../` or `..\`.
- Strings starting with `/` or `\` (forcing relative logical paths).
- Null bytes `\0`.

## 6. Infrastructure Adapter
- **LaravelFilesystemAdapter**: Adapts `Illuminate\Contracts\Filesystem\Filesystem` to the `FileStorage` contract.
- Does not leak `League\Flysystem` or `Illuminate` types into the Public API. Raw exceptions are caught and wrapped in `FileStorageFailed`.

## 7. Dependency Decisions
- **Zero Foundation Dependencies**: The package core does not depend on `Foundation.Configuration`, `Foundation.Audit`, or `Platform.Settings`. The infrastructure adapter is configured via standard Laravel mechanisms (e.g., injecting the default storage disk).

## 8. Extension Status
No extension points are strictly required for the core storage operations. It will not register passive extension points unless needed.

## 9. Manifest & Deptrac
- **Capability**: `files.storage: 0.1.0`
- **Deptrac**: Completely isolated. No upward dependencies.
