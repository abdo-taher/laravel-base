## Classes

- `ManifestReader` — framework-free Public contract returning a typed Manifest.
- `Manifest` — readonly identity and metadata value object.
- `ManifestDependency` — readonly required/optional dependency value object.
- `ManifestCapability` — readonly provided-capability value object.
- `InvalidManifest` — Public validation exception exposing ordered validation errors.
- `ManifestReadFailure` — Public file/JSON read exception.
- `ManifestFactory` — internal validation and hydration boundary.
- `JsonManifestReader` — internal JSON file reader implementing `ManifestReader`.

## Dependencies

- PHP standard library JSON and filesystem functions only for parsing and validation.
- Existing Laravel container usage is limited to `ManifestServiceProvider`; Public contracts and value objects have no Laravel dependency.
- No dependency on ModuleManager, CapabilityRegistry, DependencyResolver, project modules, extensions, database, or external provider SDKs.

## Validation Rules

- `name`, `category`, `version`, `namespace`, and `ownership` are required non-empty strings.
- Category and ownership values must belong to the accepted manifest sets.
- Version must be semantic-version formatted.
- Namespace must be a valid PHP namespace.
- `dependencies`, when present, must contain list-shaped `required` and `optional` groups; every dependency declares exactly one capability/package target and a version constraint.
- `provides`, the manifest capability declaration, must be a list of capability/version objects.
- Validation accumulates actionable errors and fails before value-object hydration.
