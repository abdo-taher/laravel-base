# A3.2 — Laravel Skeleton Baseline

## Goal

Establish the clean Laravel host application that will bootstrap the future Base modular platform.

## Scope

- Review Laravel default application code.
- Remove demo/example application behavior.
- Keep framework bootstrap and infrastructure configuration.
- Keep frontend tooling available but do not build a UI architecture yet.
- Preserve Composer and Node lockable dependency definitions.
- Validate a clean application boot.
- Create the first Git baseline only after all gates pass.

## Architecture Decision

The Laravel root application is a host/composition shell.

It must not become a business layer.

Future reusable capabilities belong in isolated modules.

Root app/ may contain only framework-level composition code that cannot reasonably belong to a module.

## Do Not Implement Yet

- Modules
- Module Manager
- SharedKernel
- Identity/Auth
- AccessControl
- Settings
- Product
- Cart
- Wallet
- PostgreSQL infrastructure
- Redis
- MinIO
- Docker
- CI/CD

## Validation Gates

- Laravel boots.
- Tests pass.
- Composer validates.
- No secrets or local database are staged.
- No generated runtime artifacts are staged.
- Governance documents exist.
- Git diff check passes.
