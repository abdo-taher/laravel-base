# B3.8 Security Foundation - Implementation Plan

## 1. Goal
Create a minimal, reusable technical Security Foundation package that provides core security primitives. This package avoids duplicating Identity (auth), AccessControl (permissions), or Observability concerns, focusing strictly on domain-neutral technical security tools.

## 2. Primitives Evaluated

### Accepted Candidates
- **SensitiveValue (Secret Handling)**: A value object that wraps a secret string, explicitly preventing accidental exposure via `__toString()`, JSON serialization, or `var_dump()` (using `__debugInfo`). Concrete need: Configuration, Audit, and Observability all handle secrets and could benefit from a unified representation.
- **SecureTokenGenerator**: A contract and implementation for generating cryptographically secure random tokens (e.g., for API keys, CSRF, nonces). Concrete need: Avoids developers falling back to `rand()`, `uniqid()`, or UUIDs for security tokens.
- **SecureCompare**: A utility/contract for constant-time string comparison to prevent timing attacks when comparing hashes or tokens.

### Rejected / Deferred Candidates
- **Hashing/Encryption**: Deferred. Identity handles passwords natively. No concrete requirement for a generic encryption contract yet.
- **Security Headers / Rate Limiting**: Deferred. These are HTTP/Infrastructure presentation concerns, not Foundation logic.
- **Request Signing / Replay Protection**: Deferred. Too specific to API infrastructure.

## 3. Secret Handling Semantics
The `SensitiveValue` class will:
- Be immutable.
- Throw an exception if `__toString()` is called.
- Return a masked string `[HIDDEN]` during serialization or debugging.
- Provide an explicit `reveal()` method for when the underlying value is actually needed by a safe consumer.

## 4. Randomness Semantics
The `SecureTokenGenerator` will rely on PHP's cryptographically secure pseudo-random number generator (CSPRNG), i.e., `random_bytes()`. It will generate hex or base64 encoded strings explicitly documenting entropy (e.g., 256 bits).

## 5. Dependencies
Zero dependencies. Does not depend on Identity, AccessControl, or external packages.

## 6. Public Boundary
No exposure of Illuminate, Monolog, or specific business vocabulary.

## 7. Tests
- Value objects must be immutable.
- `SensitiveValue` must actively block string casting and hide data in `json_encode` and `print_r`.
- `SecureCompare` must successfully match equal strings and reject unequal strings.
- Architecture rules enforce framework independence.
